# 솔버 핸드 뷰 · 포스트플랍 탐색기 설계

작성일: 2026-09-21

## 목표

솔버 탭에서 **핸드를 먼저 고정**하고, 그 핸드가 특정 포지션에서 마주치는 상황마다 **어떤 액션이 나은지**
바로 확인할 수 있어야 한다. 그리고 프리플랍에서 끝나지 않고 **플랍 · 턴 · 리버까지 이어서** 볼 수 있어야 한다.

### 현재 상태

- 프리플랍 솔버는 **레인지 우선** 흐름이다: 좌석 레일에서 상황을 고른 뒤 13×13 차트에서 핸드를 클릭해야
  그 핸드의 액션별 빈도와 EV가 보인다. 핸드를 고정해 두고 상황을 훑는 반대 방향은 없다.
- 포스트플랍 솔버(`src/engine/postflop/`)는 존재하지만 **트레이닝 모드에서 실제 핸드를 플레이할 때만**
  돌아간다. 솔버 탭에서 보드를 직접 정해 탐색할 수단이 없다.

### 범위 밖

- 3인 이상 포스트플랍 솔브. 엔진이 헤즈업만 지원한다.
- 프리플랍 레인지 뷰(현재 화면)의 동작 변경. 그대로 둔다.
- 포스트플랍 EQR 휴리스틱 개선, 프리플랍 트리·솔버 수식 변경.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 배치 | 솔버 탭 안에서 `레인지 / 핸드` 뷰 전환. 새 모드 탭을 만들지 않는다 |
| 핸드 고정 흐름 | 핸드 + 포지션을 고르면 그 포지션의 주요 상황을 **목록으로 한 번에** 보여준다 |
| 목록 범위 | 히어로 결정 2회까지, 도달 확률 임계값 이상 |
| 보드 지정 | 카드 선택기로 직접 지정 (플랍 3장 → 턴 1장 → 리버 1장) |
| 수트 | 포스트플랍은 수트까지 지정한 **콤보** 기준 |
| 엔진 배치 | 탐색 로직은 React 의존 없는 순수 모듈로 분리하고 테스트를 붙인다 |

## 화면 흐름

```
설정 패널 → 솔브 → 결과 영역 [ 레인지 | 핸드 ]
                                  │
                                  └ 핸드 뷰
                                     ├ 고정 바: 핸드(13×13 선택) + 포지션(좌석)
                                     └ 상황 목록
                                        └ 행 클릭 → 상황 상세
                                                     └ "플랍 보기" → 포스트플랍 탐색기
                                                                      플랍 → 턴 → 리버
```

레인지 뷰와 핸드 뷰는 같은 `SolveResult` · `LightTree` · `SolverConfig`를 공유한다. 뷰를 오가도 재솔브가 없다.
모바일 하단 탭(`설정 / 차트`)은 그대로 두고, 뷰 전환은 차트 화면 안에 둔다.

## 1. 상황 목록

새 모듈 `src/ui/situations.ts`. React 의존 없는 순수 함수이며 `src/ui/situations.test.ts`로 테스트한다.

### 산출 규칙

입력은 `LightTree`, `SolveResult`, 히어로 좌석, 선택한 핸드 클래스(0..168)다.

1. 루트에서 DFS로 결정 노드를 훑는다.
2. **깊이 제한** — 경로 위에서 히어로가 이미 행동한 횟수가 2 이상이면 그 가지를 더 내려가지 않는다.
   즉 히어로의 첫 결정과, 그에 대한 상대 반응 뒤의 두 번째 결정까지만 목록에 오른다.
3. **도달 확률** — 경로 위 각 단계의 빈도를 곱한다.
   - 상대 좌석의 액션: 그 좌석 레인지 전체의 빈도 (`actionTotals` 재사용)
   - 히어로 좌석의 앞선 액션: **선택한 핸드 클래스의** 빈도 (`freqOf`)
   임계값 `MIN_REACH = 0.005` 미만이면 목록에서 제외한다. 균형 전략이 거의 쓰지 않는 라인은 CFR 갱신이
   멈춰 EV가 불안정하므로(README "한계" 참고) 기본적으로 감춘다.
4. **정렬** — 히어로 결정 깊이 오름차순, 같은 깊이면 도달 확률 내림차순.
5. **상한** — 40행. 넘으면 잘라내고 "더 보기"로 나머지를 펼친다.

### 라벨

경로를 사람이 읽는 한 줄로 압축한다.

- 폴드가 연속된 구간은 생략하고, 히어로 앞에 아무도 들어오지 않았으면 `· 나머지 폴드`를 덧붙인다.
- 히어로 자신의 액션은 `내 `를 붙여 구분한다.
- 예: `첫 액션 · 나머지 폴드`, `UTG 오픈 2.0 · 나머지 폴드`, `HJ 오픈 2.0 + LJ 콜`,
  `UTG 오픈 2.0 → 내 3벳 6.6 → UTG 4벳 올인`

### 각 행에 표시할 것

- 상황 라벨, 도달 확률
- **추천 액션**: 설정의 주 단위(`config.mode`가 `icm`이면 ICM EV, 아니면 Chip EV)가 가장 높은 액션에 `▸`.
  액션 이름, 그 액션의 빈도, EV, 2등 액션과의 EV 차이를 함께 보여준다.
- **혼합 배지**: 1등과 2등의 EV 차이가 `config.smoothing`(기본 0.15bb, ICM이면 히어로의 칩 가치로 환산)
  이내이면 `혼합`을 표시한다. 거의 동등한 선택을 단일 정답처럼 보여주지 않는다.
- **희소 경고**: 경로에 `rareSteps`가 잡히면 행에 경고 아이콘을 단다.

## 2. 상황 상세

행을 클릭하면 그 자리에서 펼쳐진다.

- 액션별 빈도 / ICM EV / Chip EV 전체 표 — 기존 `HandDetail` 컴포넌트를 재사용한다.
- 그 노드의 레인지 요약(액션별 빈도·콤보) — 기존 `range-summary` 마크업 재사용.
- 코치 해설 — `src/engine/training/coach.ts`의 `explainPreflop`을 재사용한다. 다만 입력 중
  "콜하려면 에퀴티가 몇 % 필요한가"는 종료 노드의 ICM·칩 유틸리티가 있어야 하는데, 워커가 UI로 보내는
  `LightTerminal`은 payload를 줄이려고 그 값들을 뺀다. 그래서 헤즈업 올인 쇼다운의 승·패 결과를
  엔진(`buildTree`)과 같은 식(`distributeSidePots` + `icmEquity`)으로 다시 계산하는 얇은 빌더를 둔다.
  이 빌더는 엔진 트리의 실제 유틸리티와 대조하는 테스트로 고정한다.
- **포스트플랍 입구** — 이 상황에서 뻗어나가는 종료 노드 중 `tType === 'flop'`이고
  `participants.length === 2`인 것들을 모아 목록으로 보여주고 각각 "플랍 보기" 버튼을 단다.
  - 3인 이상 플랍 종료 노드는 "솔버 미지원 — 프리플랍 EV는 EQR 근사" 안내만 표시한다.
  - 히어로가 참가하지 않는 플랍 종료 노드는 표시하지 않는다.

## 3. 포스트플랍 탐색기

### 진입

선택한 프리플랍 플랍 종료 노드로부터 스팟을 구성한다.

1. **수트 지정** — 선택한 클래스의 콤보 중 하나를 고른다. 기본값은 보드와 충돌하지 않는 첫 콤보이고,
   드롭다운에서 A♠K♠ ↔ A♥K♥처럼 바꿀 수 있다.
2. **플랍 3장** — 카드 선택기로 입력한다. 히어로 카드와 중복되는 카드는 선택할 수 없다.
3. 솔브한다. 기존 `PostflopClient`(`src/ui/training/clients.ts`)를 그대로 쓴다. 진행률을 표시한다.

### 결과 화면

- 현재 결정 노드에서 **히어로 콤보**의 액션별 빈도 · ICM EV · Chip EV, 주 단위 최선 액션 표시.
  프리플랍 상황 목록과 같은 `혼합` 판정 규칙을 적용한다.
- 13×13 레인지 차트(콤보를 클래스로 집계) — `src/ui/training/RangePanel.tsx`의 표현을 재사용한다.
- 보드, 팟, 양쪽 남은 스택, 현재 행동 순서를 머리말에 표시한다.

### 경로 진행

- OOP/IP 누구 차례든 **사용자가 액션 버튼으로 직접 진행**한다. 봇도 딜링도 없다.
- 액션을 고르면 그 플레이어의 1326 콤보 레인지에 해당 액션의 전략을 곱해 좁힌다
  (트레이닝의 `applyPostflopAction`과 같은 계산).
- 뒤로 가기로 경로를 한 단계씩 되돌릴 수 있다.

### 스트리트 전환

- 체크-체크 또는 콜로 스트리트가 끝나면 다음 카드를 입력받는다 (턴 1장 → 리버 1장).
- 좁혀진 레인지와 갱신된 팟·스택으로 새 스트리트를 재솔브한다.
- 폴드 종료면 승자와 팟을, 리버 쇼다운이면 결과를 표시하고 멈춘다.
- 한쪽이 올인이라 결정이 없으면 카드만 받고 넘어간다.

### 캐시

같은 `(보드, 경로)` 키의 솔브 결과를 메모리에 보관해 뒤로 갔다 돌아올 때 재솔브하지 않는다.
보드나 수트를 바꾸면 영향을 받는 지점부터 다시 푼다. 상한은 LRU 8개로 둔다.

### 사용자에게 알릴 것

- 플랍 솔브는 턴·리버를 체크다운으로 가정한 **근사**다 (기존 트레이닝 리뷰와 같은 문구).
- 솔브 시간: PC 기준 플랍 약 2~3초, 턴 약 4초, 리버 0.2초. 휴대폰은 더 느리다.

## 4. 엔진 모듈

### 신규 `src/engine/postflop/spot.ts` — 공유 헬퍼

```ts
/** 169 클래스 reach → 1326 콤보 가중치 */
export function classToComboWeights(reach: Float64Array): Float64Array;

export interface PreflopExit {
  seats: [number, number];          // [OOP, IP] (postflopRank 순)
  ranges: [Float64Array, Float64Array];
  pot: number;
  base: number[];                   // 프리플랍 종료 후 좌석별 남은 칩
  icm: PostflopSpot['icm'];
}

/**
 * 프리플랍 플랍 종료 노드에서 포스트플랍 시작 상태를 만든다.
 * 좌석별 reach(169 클래스)는 호출자가 경로에서 계산해 넘긴다 — 엔진 모듈이
 * UI(`src/ui/spot.ts`)나 워커 프로토콜 타입에 의존하지 않게 하기 위해서다.
 */
export function preflopExit(input: {
  config: SolverConfig;
  participants: number[];           // 종료 노드의 participants
  pot: number;
  contrib: number[];                // 종료 노드의 좌석별 프리플랍 투입액
  reachBySeat: Float64Array[];      // 좌석 인덱스별 169 클래스 reach
}): PreflopExit;
```

앤티(BB만 부담)와 상금 정규화는 헬퍼가 `config`에서 직접 유도한다. 두 호출자가 서로 다르게 계산할 여지를 없앤다.

`src/engine/training/hand.ts`의 `preflopTerminal`(헤즈업 분기)과 `icmContext`가 이 헬퍼를 쓰도록 바꾼다.
이것이 `hand.ts`에 가하는 **유일한 수정**이며, 트레이닝과 탐색기가 같은 계산을 한다는 것을 구조로 보장한다.

### 신규 `src/engine/postflop/explore.ts` — `PostflopExplorer`

React 의존이 없다. `PostflopService`(기존 인터페이스)를 주입받는다.

```ts
export class PostflopExplorer {
  constructor(exit: PreflopExit, hero: { seat: number; combo: number }, service: PostflopService);

  readonly state: ExploreState;        // street, board, node, tree, result, ranges, status
  subscribe(fn: () => void): () => void;

  setBoard(cards: number[]): Promise<void>;   // 필요한 장수를 받아 해당 스트리트를 솔브
  act(action: number): Promise<void>;         // 현재 노드에서 액션 진행 (스트리트 종료면 카드 대기)
  undo(): Promise<void>;
  setHeroCombo(combo: number): Promise<void>;
}
```

상태 갱신은 `TrainingHand`와 같은 구독 방식을 따른다 (`listeners` + 불변 뷰 객체).

## 6. 테스트

기존 `npm test`(vitest)로 돌아간다.

- `src/ui/situations.test.ts`
  - 히어로 결정 3회째 라인은 목록에 없다
  - 도달 확률이 임계값 미만인 라인은 제외된다
  - 폴드 연속 구간이 라벨에서 압축된다
  - EV 차이가 smoothing 이내이면 `혼합`으로 판정된다
- `src/engine/postflop/explore.test.ts`
  - 같은 프리플랍 스팟에서 `preflopExit`가 `hand.ts`의 헤즈업 진입과 같은 스팟·레인지·ICM 컨텍스트를 만든다
  - 액션을 진행하면 그 플레이어 레인지가 전략만큼 좁혀진다
  - 체크-체크 뒤 다음 스트리트 카드를 요구하고, 카드를 주면 재솔브한다
  - 같은 (보드, 경로)로 돌아오면 솔브를 다시 호출하지 않는다 (가짜 `PostflopService`로 호출 횟수 확인)
- 기존 테스트는 모두 통과해야 한다 (`hand.ts` 수정이 회귀를 내지 않는지 확인).

## 7. 한계 (화면에 명시)

- **포스트플랍은 헤즈업 전용.** 3인 이상으로 플랍에 가는 라인은 프리플랍 EV(EQR 근사)까지만 제공한다.
- 플랍 솔브는 턴·리버 체크다운 가정 근사다.
- 매 스트리트 실시간 솔브이므로 즉답이 아니다 (플랍 2~3초, 턴 4초).
- 프리플랍은 169 클래스 단위라 상황 목록의 수트별 차이는 반영되지 않는다. 수트는 포스트플랍 진입 시점에
  지정한다.
