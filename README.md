# ICM Preflop Lab

토너먼트(MTT) 프리플랍 GTO 솔버 웹앱. 2~8인 테이블에서 좌석별 스택, BB 앤티, 상금 구조(ICM)를 반영해
핸드별 액션 빈도와 EV(ICM · Chip)를 13×13 차트로 보여준다. PC와 휴대폰 브라우저 모두 지원한다.

## 실행과 접속

```bash
npm install
npm run dev        # 개발 서버: http://localhost:5391 (같은 네트워크의 휴대폰은 http://<PC IP>:5391)
npm run build      # dist/ 에 정적 파일 생성 (상대 경로라 어떤 정적 호스팅에도 올릴 수 있음)
npm run preview    # 빌드 결과 서버: http://<PC IP>:4173
npm test           # 엔진 테스트
npm run audit      # 정확도 감사 (몬테카를로 기준값과 비교, docs/accuracy-report.md 생성)
npm run build:pool # 트레이닝용 시나리오 풀을 미리 솔브해 public/pool/ 에 저장
```

**휴대폰에서 접속하기**
1. PC와 휴대폰을 같은 Wi-Fi에 연결한다.
2. `npm run dev` 실행 시 표시되는 `Network:` 주소를 휴대폰 브라우저에 입력한다.
3. 접속이 안 되면 Windows 방화벽에서 Node.js의 개인 네트워크 접근을 허용한다.
4. 외부에서도 쓰려면 아래 "Vercel 배포"처럼 정적 호스팅에 올린다.

모바일 화면은 하단 탭(설정 / 차트)으로 전환하고, 핸드를 탭하면 액션별 빈도와 EV가 바텀시트로 뜬다.
솔버는 브라우저 Web Worker에서 돌며, PC는 최대 12스레드, 휴대폰은 최대 4스레드를 쓴다
(중첩 워커를 지원하지 않는 브라우저는 자동으로 단일 스레드로 전환).

## Vercel 배포 (정적 호스팅, 서버 비용 없음)

서버 코드는 없다. 프리플랍 시나리오 풀은 로컬 PC에서 미리 솔브해 정적 파일로 함께 올리고,
포스트플랍 솔브와 EV 계산은 접속한 사용자의 브라우저에서 돈다.

1. 풀 생성 (로컬, 28스레드 PC에서 수십 분):
   ```bash
   npm run build:pool -- --clean               # 기본: 용량 70MB, 300회 반복
   npm run build:pool -- --budget-mb 85        # 이어서 더 채우기 (중단해도 이어짐)
   ```
   `public/pool/manifest.json`과 테이블 파일(`*.icp`, 12비트 로그 양자화 전략 + gzip)이 생긴다.
   8인 25bb 테이블 약 1.3MB, 깊은 스택은 3~9MB.
2. `public/pool/`까지 커밋해 GitHub에 올리고, Vercel에서 저장소를 Import 한다.
   `vercel.json`에 빌드 명령(`npm run build`), 출력 폴더(`dist`), 캐시 헤더가 들어 있다.
   CLI로 올릴 때는 `npx vercel --prod`.
3. 엔진(트리·솔버 수식)을 바꾸면 풀을 다시 만든다. 트리 모양이 다른 파일은 브라우저가 자동으로 무시하고,
   트리 모양은 같지만 수식이 바뀐 경우에는 `src/engine/training/prebuilt.ts`의 `PREBUILT_VERSION`을 올린다.

**Vercel Hobby(무료) 한도:** 비상업적 개인 용도만 허용 (광고·결제가 붙으면 Pro 필요),
정적 파일 업로드 100MB(CLI 기준), 월 전송량 100GB. 풀 파일은 해시 이름이라 한 번 받은 사용자는 다시 받지 않는다.

## 트레이닝 모드

상단 `트레이닝` 탭에서 무작위 토너먼트 핸드를 플레이하며 결정마다 리뷰를 받는다.

- **시나리오 풀:** 미리 솔브된 테이블(`public/pool`) 중 출제 범위(인원, 스택 범위, 판단 기준)에 맞는 것을 내려받아
  EV를 다시 계산해 IndexedDB에 저장한다 (PC 6개, 휴대폰 3개). 맞는 테이블이 없으면 그때만 브라우저에서 무작위 테이블을 솔브한다.
  테이블 하나를 25핸드까지 쓰고, 최근에 쓰지 않은 테이블로 교체한다.
- **핸드 진행:** 8명 전원에게 실제 카드를 딜링하고, 봇은 솔버 전략을 샘플링해 행동한다. 히어로 포지션은 무작위.
- **리뷰:** 히어로가 액션을 고르면 즉시 GTO 빈도, 액션별 ICM EV(%p)·Chip EV(bb), 최선 대비 손실과 판정
  (최선 / GTO 혼합 / 부정확 / 실수 / 큰 실수)을 보여준다. 핸드 기록에서 이전 결정의 리뷰를 다시 열 수 있다.
- **레인지 리뷰:** 같은 결정에서 히어로 레인지 전체의 액션별 빈도·평균 EV, GTO 레인지 EV, 13×13 차트(전략 / 액션별 EV)를
  함께 보여준다. 리뷰 표의 액션을 누르면 그 액션의 핸드별 EV 차트로 바뀐다 (프리플랍, 헤즈업 포스트플랍).
- **코치 해설:** 결정마다 "왜 이 판단인가"를 솔버 수치에서 규칙으로 뽑아 설명한다. 칩 EV와 ICM의 차이, 올인 콜의
  필요 에퀴티(칩·ICM 기준)와 상대 레인지 대비 에퀴티, 버블·커버 여부·짧은 스택 수, 포지션별 오픈 레인지와 핸드 순위,
  메이드 핸드·드로우, 밸류/블러프/팟 컨트롤 분류, 넛 우위, SPR, 블로커, 혼합 전략 여부를 다룬다 (`src/engine/training/coach.ts`).
- **핸드 리뷰:** 핸드가 끝나면 등급, 총 EV 손실, 가장 큰 실수와 그 이유, 이번 핸드의 교훈을 정리한다.
- **포스트플랍 (헤즈업):** 스트리트마다 레인지를 좁혀 실시간 솔브한다 (1326 콤보 DCFR, 종료 노드마다 ICM).

| 스트리트 | 솔브 방식 | PC 시간 (12스레드) |
|---|---|---|
| 플랍 | 턴·리버를 체크다운 에퀴티로 가정한 깊이 제한 솔브 (근사, 리뷰에 표시) | 약 2~3초 |
| 턴 | 리버 44장 전부와 리버 베팅(75%·올인)까지 포함, 리버 카드별 병렬 | 약 4초 |
| 리버 | 쇼다운까지 정확 | 0.2초 |

- **포스트플랍 (3~4인):** 솔버 미지원. 봇은 에퀴티 기반 규칙으로 행동하고, 리뷰는 상대 레인지 대비 에퀴티와
  폴드·체크·콜의 근사 Chip EV만 제공한다.
- **베팅 사이즈:** 플랍 33%·75%·레이즈 75%·올인, 턴 66%·올인, 리버 50%·100%·레이즈 75%·올인.
- **검증:** 리버 폴라라이즈드 블러프캐처 게임에서 밸류 3/3, 블러프 1.50콤보, 콜 50.0% (이론값과 일치),
  병렬 턴 솔브와 단일 스레드 결과 일치, 무작위 핸드 시뮬레이션에서 칩 보존.

## 게임 모델

**액션 트리**
- 오픈(사이즈 설정), SB 림프, 3벳(IP/OOP 배수 + 스퀴즈 콜러당 추가), 4벳, 올인
- 사이즈가 스택의 `올인 전환 비율` 이상이면 해당 사이즈를 빼고 올인만 남긴다
- 콜로 팟 인원이 4명 이상이 되는 라인은 제외. 액션을 닫는 마지막 콜(올인 아님)만 4인까지 허용
- 올인한 플레이어가 이미 3명이면 추가 레이즈 불가 (4인 올인 방지)
- 3벳 이후 콜드콜 불가 (올인에 대한 콜은 가능), 콜드 4벳은 올인만

**종료 노드 가치**

| 종료 유형 | 계산 방식 |
|---|---|
| 모두 폴드 | 칩 이동 → ICM (정확) |
| 2인 올인 | 169×169 에퀴티 × ICM, 사이드팟 |
| 3인 올인 | 1:1 에퀴티 + 멀티웨이 모델로 1등 확률, 나머지 순위는 1:1 에퀴티에서 정확히 유도 |
| 플랍 진행 (2~4인) | 멀티웨이 승률 × EQR(포지션·SPR·플레이어빌리티) → 승자 추첨, 패자는 `팟 성장`만큼 추가 손실 (휴리스틱) |

**카드 제거**
- 히어로와 각 상대 사이: 콤보 단위 정확 호환성
- 폴드한 플레이어: 폴드 시점에 남은 플레이어 레인지를 폴드 레인지와의 호환 확률로 가중
- 보드 분포: 폴드한 레인지가 가져간 브로드웨이 카드 수의 기대 편차 × 에퀴티 민감도 행렬

**멀티웨이 모델** (`scripts/gen-multiway.ts`)
보드별 콤보 백분위 강도 s로 `P(모든 상대를 이김) = E_board[s^(κ·Σγ_i)]`, γ_i는 1:1 에퀴티에 맞춘 지수.
실제 카드 몬테카를로와 비교한 검증 세트 평균 오차는 3인 1.3%, 4인 1.7%다 (기존 곱셈 근사는 8.9%, 11.7%).

**EV가 비슷한 액션의 빈도 분할** (`smoothing`, 기본 0.15bb)
DCFR은 EV가 조금이라도 높은 액션으로 쏠려서, 0.05bb 차이인데 99% : 1%처럼 나오는 경우가 많다.
솔브가 끝나면 핸드마다 각 액션에 `exp((EV − 최고 EV) / τ)` 비율만큼 최소 빈도를 보장하고 다시 정규화한다
(τ는 bb 단위, ICM에서는 플레이어별 칩 가치로 환산). 솔버가 이미 섞던 비율은 유지되고, EV가 크게 뒤지는 액션은 0으로 남는다.
예: 8인 33bb 파이널 테이블 SB JTs(림프와 레이즈 차이 약 0.08bb)는 림프 99.8% → 림프 78% · 레이즈 20%.
착취 가능도는 약 0.001%p에서 0.024%p(약 0.08bb)로 늘어난다. 모든 플레이어의 응답을 다시 맞추는 로짓 균형 반복은
트리 전체로 연쇄 변화가 생겨 불안정했기 때문에 한 번만 적용한다.

**프리플랍 공격자 보정 검증** (`.audit/calibrate-eqr.ts`)
플랍 진행 종료 노드의 EQR이 "프리플랍 레이저인지"를 반영하지 않는 문제를 포스트플랍 솔버로 검증했다.
8인 20·30·50bb, 6인 25bb 칩 테이블에서 자주 나오는 헤즈업 플랍 라인 44개를 플랍 12개씩 솔브해,
각 라인의 실현률 비율을 역산했다. OOP 레이저 팟과 IP 레이저 팟을 비교하면 공격자 효과는 ×1.007로 사실상 0이어서
보정 계수(`postflop.aggressor`)는 1로 둔다. 특정 핸드(예: SB JTs 레이즈 후 콜)에서 보이는 차이는
레인지 전체의 공격자 효과가 아니라 핸드별 실현률 차이이며, 참조 솔브도 턴·리버를 체크다운으로 가정하는 한계가 있다.

ICM EV 단위는 핸드 시작 시점 대비 상금 풀 지분 변화(%p), Chip EV는 칩 변화(bb)다.
블라인드와 앤티 투입분이 포함되므로 BB의 폴드 EV는 `-(1 + 앤티)`bb다.

## 정확도 감사

`npm run audit`은 스팟마다 솔브한 뒤, 같은 전략을 실제 카드 딜링으로 따라가는 몬테카를로 기준값과
핸드별 EV를 비교한다 (핸드당 4만 샘플, 전원 카드 제거, 동률 사이드팟, ICM). 전체 결과는
[docs/accuracy-report.md](docs/accuracy-report.md).

| 스팟 (8인 25bb 파이널 테이블, ICM) | EV 오차 평균 | 전략 손실 평균 |
|---|---|---|
| UTG 첫 액션 | 0.005%p | 0.000%p |
| BB vs BTN 오픈 | 0.012%p | 0.002%p |
| BB vs CO 오픈 + BTN 콜 (3인) | 0.032%p | 0.003%p |
| SB 첫 액션 | 0.007%p | 0.001%p |
| BTN vs CO 오픈 | 0.006%p | 0.002%p |
| 스택 편차 · CO vs UTG 7bb 올인 | 0.002%p | 0.001%p |
| 버블 · BB 60bb vs SB 40bb 올인 ※ | 0.005%p | 0.001%p |
| BB vs BTN 25bb 올인 ※ | 0.009%p | 0.017%p |
| SB vs BTN 25bb 올인 ※ | 0.010%p | 0.012%p |
| HU 10bb Chip EV 푸시/폴드 | 0.014bb | 0.001bb |

※ 균형 전략에서 거의 선택되지 않는 액션(0.00%)을 거친 **희소 라인**.
포스트플랍이 들어가는 스팟은 EQR 휴리스틱을 끈 중립 모델로 감사했다 (휴리스틱 자체는 포스트플랍 솔버 없이는 검증할 수 없음).
감사는 솔버 계산 자체를 확인하므로 빈도 분할(smoothing)을 끄고 돌린다.

감사 과정에서 고친 것:
- 3인 이상 승률을 1:1 승률의 곱으로 근사해 3인 팟 콜 EV가 체계적으로 낮게 나오던 문제 (전략 손실 0.104 → 0.003%p)
- 폴드한 플레이어의 카드 제거 누락 (BB vs BTN 올인 EV 오차 0.021 → 0.009%p)
- 스택이 서로 다를 때 4인 올인 라인이 만들어져 솔브가 실패하던 트리 버그
